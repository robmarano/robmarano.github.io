# ECE 465: Cloud Computing - Final Project Grading Rubric

**Total Points:** 180
**Project Type:** Individual MVP (Minimum Viable Product)
**Submission Deadline:** Last Class by 11:59:59 PM ET

This rubric outlines the evaluation criteria for the ECE 465 final project, designed to assess your mastery of distributed systems engineering, software architecture design, project management, and practical implementation.

---

## 1. System Architecture & Design Documentation (40 Points)
*It is critical to document design in diagrams and in words on your repo project's wiki.*

*   **[15 pts] Architectural Diagrams:** Clear, accurate, and professional system architecture diagrams (e.g., using draw.io/Mermaid) illustrating the distributed nature of the MVP, including nodes, networks, and data flow.
*   **[15 pts] Subsystem Design Specifications:** Detailed technical documentation in the GitHub Wiki explaining the design, purpose, and tradeoffs of each individual subsystem (e.g., compute, coordination, storage, security).
*   **[10 pts] Distributed Tenets Analysis:** Written explanation of how the design addresses core distributed systems tenets (e.g., scalability, fault tolerance, consistency, availability).

## 2. Technical Implementation & Source Code (60 Points)
*Source code must be maintained in the assigned GitHub repository.*

*   **[20 pts] Distributed Logic & Concurrency:** Successful implementation of multi-threaded/concurrent logic across networked nodes rather than a uniprocessor monolith.
*   **[20 pts] Core Distributed Components:** Practical application of at least one major distributed systems pattern (e.g., coordination/ZooKeeper, load balancing, fault tolerance masking, security, or replication).
*   **[10 pts] Code Quality & Structure:** Code is clean, well-organized, commented, and follows standard software engineering practices.
*   **[10 pts] Version Control Best Practices:** Consistent, descriptive Git commits demonstrating iterative development throughout the semester (not just a single massive commit at the deadline).

## 3. Project Management & Task Tracking (30 Points)
*Breakdown the MVP design into manageable sets of tasks, tracked via GitHub Projects.*

*   **[15 pts] Work Breakdown Structure:** The MVP is logically decomposed into epics, issues, and actionable tasks.
*   **[15 pts] Agile Tracking:** Active and visible use of the GitHub Project board (To Do, In Progress, Done) demonstrating steady progress tracking throughout the project lifecycle.

## 4. Final Presentation & Video Demonstration (50 Points)
*Demonstrate the MVP as part of your final presentation in an unlisted YouTube video.*

*   **[20 pts] MVP Functionality Demo:** The video successfully proves that the MVP works as designed. It clearly demonstrates the distributed components interacting and functioning under normal (and potentially faulty) conditions.
*   **[15 pts] Technical Explanation:** The presentation effectively walks the audience through the underlying architecture, challenges faced, and how distributed computing problems were solved.
*   **[15 pts] Presentation Quality:** The video is professional, well-paced, within the allotted time limit, with clear audio and visual quality (Unlisted YouTube link provided on time).

---

### Grade Scale Mapping
*   **A:** 162 - 180 points (Exceptional distributed design and implementation)
*   **B:** 144 - 161 points (Solid working MVP with minor documentation/design flaws)
*   **C:** 126 - 143 points (MVP functions partially; major concepts or tenets missing)
*   **D:** 108 - 125 points (Incomplete MVP; poor project management and documentation)
*   **F:** < 108 points (Failed to meet minimum requirements or no submission)
